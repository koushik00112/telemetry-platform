# Telemetry Platform

[![CI](https://github.com/koushik00112/telemetry-platform/actions/workflows/ci.yml/badge.svg)](https://github.com/koushik00112/telemetry-platform/actions/workflows/ci.yml)

Devices send sensor readings to an HTTP API. The API authenticates each device, validates
and stores its readings (skipping duplicates), and serves them back by time range. A
background worker raises and resolves threshold alerts. The whole stack runs locally with
Docker Compose, and on AWS (ECS Fargate, RDS Postgres) from Terraform with a gated
deploy pipeline.

> **Data:** all device data in this repo is **synthetic**, generated by the included
> simulator. No real hardware is involved.

[Threat model](docs/threat-model.md) · [Load-test method](docs/loadtest.md) ·

## What it does

- **Ingest**: single readings or batches of up to 1000, authenticated per device.
  Duplicates of (device, metric, timestamp) are skipped and counted, not errors.
  Retries with the same `Idempotency-Key` return the original response.
- **Query**: readings by time range and metric. A device can only read its own data.
- **Alerts**: threshold rules (`gt`/`lt`). A worker claims readings with
  `FOR UPDATE SKIP LOCKED`, opens an alert on the first breach and resolves it on the next
  normal reading ([ADR 0002](docs/adr/0002-alert-worker-claims-rows-with-a-flag.md)).
- **Simulator**: N devices with seeded spike, stuck, drift and dropout faults. It writes
  the ground truth to CSV, and batches retry with idempotency keys.
- **Operability**: JSON logs with request ids, Prometheus metrics, a Grafana dashboard as
  code, and a clean 503 with `Retry-After` when the database is down.
- **Delivery**: GitHub Actions for lint, types and tests (with real Postgres), security
  scans, Terraform validation, and a compose smoke test plus DB-outage drill. Deploys to
  AWS after manual approval, using OIDC with no stored keys.

## Quick start (local)

Requires Docker.

```bash
docker compose up -d --build api worker         # Postgres, migrations, API :8000, worker
pip install -e .
python scripts/smoke.py                          # waits for the API, then register, ingest, query

# Alert rule + 6 h backfill from 20 simulated devices with injected faults
curl -X POST localhost:8000/alert-rules -H 'X-Admin-Token: dev-admin-token' \
     -H 'Content-Type: application/json' -d '{"metric":"temperature_c","operator":"gt","threshold":32}'
python -m simulator --devices 20 --interval 60 --duration 21600 --backfill --fault-rate 0.02
curl 'localhost:8000/alerts?status=resolved' -H 'X-Admin-Token: dev-admin-token'

docker compose --profile observability up -d     # Grafana http://localhost:3000, Prometheus :9090
scripts/db_outage_drill.sh                       # stop the DB, expect 503, measure recovery
```

API docs: http://localhost:8000/docs

## API

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/livez` | none | Process is up (load balancer health check) |
| GET | `/healthz` | none | Database reachable (503 if not) |
| POST | `/devices` | `X-Admin-Token` | Register a device; returns its API key **once** |
| POST | `/readings` | `X-API-Key` | One reading `{metric, value, ts}`. 201 if new, 200 if duplicate |
| POST | `/readings/batch` | `X-API-Key` | Up to 1000 readings; optional `Idempotency-Key` |
| GET | `/devices/{id}/readings?start&end[&metric][&limit]` | `X-API-Key` | Readings in `[start, end)`, oldest first |
| POST/GET | `/alert-rules` | `X-Admin-Token` | Create or list rules `{metric, operator: gt\|lt, threshold}` |
| GET | `/alerts?status&device_id` | `X-Admin-Token` | Alerts, newest first |
| GET | `/metrics` | internal only | Prometheus metrics (blocked at the public load balancer) |

Validation: metric names are `snake_case`; values must be finite; timestamps need a
timezone and may be at most 5 minutes in the future. API keys are stored only as SHA-256
hashes.

## Deploying to AWS

See the [runbook](docs/runbook.md). In short: `infra/bootstrap` (budget alarm, state
bucket, CI roles), then `infra/app` (VPC, RDS, ECS, ALB, secrets, alarms), then the Deploy
workflow. It costs about $65/month if left running (estimate,
[ADR 0003](docs/adr/0003-fargate-without-nat.md)), so it's designed to be torn down with
`terraform destroy` between demos.

## Development

```bash
make install      # venv with dev + load-test extras
make lint         # ruff + mypy (strict)
make test         # unit tests with coverage
make test-integration   # against Postgres in Docker
```

Layout: `app/` (API, models, services, worker), `simulator/`, `tests/unit`,
`tests/integration`, `alembic/` (migrations), `infra/` (Terraform), `observability/`
(Prometheus and Grafana as code), `loadtest/`, `scripts/`, `docs/`.

## Limitations

Known gaps are listed in the [threat model](docs/threat-model.md). The main ones: no rate
limiting, HTTP only until a domain and certificate are configured, a single admin token,
and alert ordering is only guaranteed with one worker.
